# Playino : Escape Room — 기술 사양 (Tech Spec)

> 새 작업지침서의 **"기술 사양"** 섹션으로 그대로 사용 가능. 기준일: 2026-06-05

---

## 1. 기술 스택

| 항목 | 사용 | 비고 |
|---|---|---|
| **언어** | **JavaScript (ES Modules)** | TypeScript 아님 · 바닐라 JS |
| **게임 엔진** | **Phaser 3 (v3.90.0)** | MIT 라이선스 · 무료 · 상업적 사용 가능 |
| **빌드 도구** | **Vite 6** | dev 서버 + 정적 빌드(`dist/`) |
| **렌더러** | `Phaser.AUTO` | WebGL 우선, 실패 시 Canvas 자동 폴백 |
| **폼/입력 UI** | DOM 오버레이(`#overlay`) | 로그인 등 네이티브 `<input>` 필요한 곳 |
| **배포** | Vercel 정적 호스팅 | `base: './'` (상대 경로) |
| **상태 저장** | `localStorage` | 백엔드 없음(서버리스) |
| **유료 엔진** | **금지** | 런타임 라이선스 비용 0 (접속코드 판매 구조) |

## 2. 프레임(캔버스) 사이즈 — ★핵심

```
기준 해상도(논리 좌표계) : 1280 × 720  (16:9)
스케일 모드               : Phaser.Scale.FIT + CENTER_BOTH (비율 유지·가운데 정렬·레터박스)
```

- **모든 좌표·배치는 1280 × 720 기준**으로 작성한다. 실제 화면 크기가 달라도 Phaser가 비율을 유지하며 자동으로 확대/축소(FIT).
- 덕분에 **배경 아트 ↔ 게임 좌표가 1:1 매칭** → 그림 위 버튼/입력 위치를 정확히 얹을 수 있음.
- 단일 관리: `src/shared/theme.js` 의 `BASE = { w: 1280, h: 720 }`.

## 3. 에셋(이미지) 규격

| 종류 | 권장 크기 | 포맷 | 비고 |
|---|---|---|---|
| **배경(풀스크린)** | **2560 × 1440** | PNG | 1280×720의 2배(선명) · **16:9 정확히** |
| 캐릭터/소품 | 실사용의 약 2배 | PNG(투명) | 중앙 정렬, 여백 최소 |
| 폴더 | `public/assets/<장면>/` | — | `title/ login/ hub/ rooms/ characters/ ui/` |

- ⚠️ **반드시 16:9** (2560×1440 권장). 비율이 다르면 화면 채움(cover) 시 가장자리가 잘려 좌표가 어긋남.
- 파일명은 장면 폴더에 `bg.png` 권장(로더가 `bg.*`, 장면명.* 도 인식).
- 배경에 **기능 UI(입력칸·버튼 텍스트)를 그려 넣을 경우**, 그 위에 투명 작동 영역을 얹는다(좌표 1:1이라 가능). 새로 만들 땐 **기능 영역을 비워** 두는 편이 유지보수에 유리.

## 6. 프로젝트 구조 / 컨벤션

```
public/assets/<장면>/      # 이미지(있으면 자동 사용, 없으면 절차적 폴백)
src/
  main.js                  # 엔트리(폰트 로드 후 게임 부팅)
  game/
    config.js              # Phaser 설정(해상도·스케일·씬 등록)
    assets.js              # 에셋 슬롯 탐지(resolveAssets)
    scenes/                # Boot→Preload→Splash→Title→Login→ComingSoon …
    objects/               # 재사용 객체: Button / Eddie / CodeInput
    fx/                    # 연출: textures(글로우·먼지·비네트·cover), transition(페이드)
  ui/                      # DOM 오버레이(login 등)
  shared/theme.js          # 팔레트·폰트·BASE 해상도·씬키
  styles/app.css
docs/                      # 지침서/사양서
```

**핵심 규칙**
- 화면 1개 = **Phaser 씬 1개** (`extends Phaser.Scene`).
- 씬 전환은 트윈 기반 페이드 `goTo(scene, key)` 사용(카메라 fade 이벤트 의존 X).
- 모든 좌표는 1280×720. 배경 아트 위 작동 영역은 같은 좌표계의 투명 `zone`/객체로 얹는다.
- 가산 발광은 `Phaser.BlendModes.ADD` (단수 `BlendMode` 아님 — 주의).
- 정리(`destroy`/`shutdown`)에서 타이머·키보드·리스너 해제(누수 금지).

## 7. 실행/배포

```bash
npm install
npm run dev      # http://localhost:5173 (점유 시 5174 …)
npm run build    # dist/ 정적 산출물 → Vercel
```

- 하드웨어 테스트: 크롬 계열 + WebSerial(데스크톱). 권한은 사용자 클릭에서 요청.
- 브랜치 규칙: 지정 기능 브랜치에서 작업, `package-lock.json` 은 .gitignore.
